推荐方案是新建一个 ops-dashboard 子项目，采用 React + Ant Design 前端、NestJS + Prisma + SQLite 后端，单机 Docker 部署。核心实现方式不是直接对原始地址做跨域自动填充，而是通过 Dashboard 的代理入口访问目标系统：普通登录页由服务端先换取会话再进入系统；带验证码的系统走“自动预填账号密码 + 人工补验证码”的半自动模式。这样最符合你要的统一入口、状态可视化、后续可扩展和一键直达。

关键决定

部署方式：单机 Docker。
凭据策略：允许服务端加密保存。
用户模型：首版使用共享凭据。
访问方式：接受通过 Dashboard 代理入口访问目标系统。
自动登录深度：能自动登录的系统直接登录；有验证码的系统只做到预填账号密码，验证码由人工补。
范围边界

包含：统一状态看板、目标管理、加密凭据、共享账号、一键进入、后续可新增更多系统。
暂不包含：验证码绕过、MFA 自动化、按 Dashboard 用户分别保存不同凭据、多节点高可用。
